# Project Instructions

This project follows a simple decision process:

1. Finish the current task.
2. Record what was learned.
3. Identify the next concrete step.
4. Store side ideas separately.


## Documentation Ownership

This project owns its own copies of:

- AGENTS.md
- README.md
- JOURNAL.md
- IDEAS.md

Do not rely on shared template files after project creation.

Project documentation should evolve with the project.


## Session Summary

When the user ends a work session with phrases such as:

- good night
- thanks for today
- let's continue tomorrow
- end session
- summarize today

update JOURNAL.md.

Add the newest entry at the top of the journal section.

Use this format:

## YYYY-MM-DD

Done:
One sentence.

Learned:
One sentence.

Next:
One sentence.

Open Questions:
One sentence.


## Focus Rule

Always prefer finishing an existing task before starting a new feature.


## Documentation Rule

Update README.md only when the user-visible functionality,
project purpose, architecture or setup instructions have changed.

Do not update README.md for small fixes, refactoring or routine maintenance.

Keep README.md short and current.


## Idea Management

Capture all project-related ideas in IDEAS.md.

Sort ideas into three categories:

### Seeds
Raw thoughts, observations or possibilities that need substantial exploration.

Examples:
- Could this work with voice input?
- What if cards could be linked together?
- Maybe there is a way to detect trends automatically.

### Concepts
Ideas with a clearer purpose, user value and rough implementation approach.

Examples:
- Add voice notes to cards.
- Link cards into story chains.
- Weekly trend analysis dashboard.

### Candidates
Well-defined ideas that could reasonably be implemented in a future sprint.

Examples:
- Add microphone button to card editor.
- Create card-link relationship table.
- Build trend summary page.

When an idea becomes significantly clearer, move it to the next category.

Keep descriptions short, usually one sentence.
Avoid losing ideas in chat history.


## Next Step Rule

JOURNAL.md should always contain a clearly visible "Current Next Step" section at the top.
